บทที่ 1 · AIoT คืออะไร

1 คาบไม่ต้องใช้อุปกรณ์

จุดประสงค์

  • อธิบายความหมายของ IoT, AI และ AIoT ได้
  • แยกองค์ประกอบ 4 ส่วนของระบบ AIoT: วัด (Sense) → ส่ง (Connect) → คิด (Think) → ตอบสนอง (Act)

เนื้อหา

IoT

อุปกรณ์ที่มีเซนเซอร์และต่ออินเทอร์เน็ตได้ เช่น มิเตอร์ไฟอัจฉริยะ กล้องวงจรปิด เครื่องวัดฝุ่น PM2.5

AI

โปรแกรมที่ "เรียนรู้จากตัวอย่าง" แทนการเขียนกฎทุกข้อเอง เช่น ระบบแนะนำวิดีโอ การสแกนใบหน้า

AIoT

IoT ที่มี AI ช่วยตัดสินใจ เช่น ฟาร์มอัจฉริยะที่รดน้ำเมื่อ AI คาดว่าดินจะแห้ง โรงงานที่ AI เตือนก่อนเครื่องจักรเสีย

กิจกรรม: "ห้องเรารู้สึกอย่างไร?" (15 นาที)

  1. ครูอ่านค่าอุณหภูมิจากเทอร์โมมิเตอร์หรือหน้า Dashboard (โหมดจำลองก็ได้)
  2. นักเรียนแต่ละคนเขียนความรู้สึก: เย็นไป / สบาย / ร้อนไป / อบชื้น
  3. นับคะแนนบนกระดาน แล้วถามว่า "ถ้าจะให้คอมพิวเตอร์ตอบแทนเรา ต้องสอนมันอย่างไร?"
คำถามท้ายบท
  1. ยกตัวอย่างระบบ AIoT ในชีวิตประจำวัน 2 ตัวอย่าง และระบุส่วน วัด/ส่ง/คิด/ตอบสนอง ของแต่ละระบบ
  2. ถ้าใช้แค่กฎ "อุณหภูมิเกิน 30 องศา = ร้อน" จะมีปัญหาอะไรบ้าง?

บทที่ 2 · รู้จักบอร์ด Cucumber และอ่านค่าเซนเซอร์

2 คาบบอร์ด + คอมพิวเตอร์

จุดประสงค์

  • ติดตั้งเครื่องมือและอัปโหลดโปรแกรมลงบอร์ด ESP32-S2 ได้
  • อ่านค่าเซนเซอร์และอธิบายได้ว่าแต่ละตัววัดอะไร

เซนเซอร์บนบอร์ด Cucumber RIS

ชิปวัดอะไรที่อยู่ I2Cใช้ในโปรเจกต์
HTS221อุณหภูมิ, ความชื้นสัมพัทธ์0x5Fข้อมูลเข้าของ AI
BMP280ความกดอากาศ0x76/0x77แสดงผล
MPU-6050ความเร่ง 3 แกน, ไจโร 3 แกน0x68วัดการสั่น (โปรเจกต์ต่อยอด)
WS2812 (NeoPixel)ไฟ LED สีGPIO18แสดงผลของ AI

ขั้นตอน

  1. ติดตั้ง Arduino IDE 2 → File → Preferences → Additional boards manager URLs ใส่
    https://espressif.github.io/arduino-esp32/package_esp32_index.json
  2. Tools → Board → Boards Manager → ติดตั้ง esp32 by Espressif Systems
  3. Library Manager → ติดตั้ง PubSubClient, ArduinoJson, Adafruit HTS221, Adafruit BMP280 Library, Adafruit MPU6050, Adafruit NeoPixel (กด Install all เมื่อถามเรื่อง dependency)
  4. ในโฟลเดอร์ firmware/cucumber_aiot/ คัดลอกไฟล์ secrets_example.h แล้วตั้งชื่อใหม่เป็น secrets.h ใส่ชื่อและรหัส WiFi: 
    const char* WIFI_SSID     = "ชื่อ WiFi";
const char* WIFI_PASSWORD = "รหัส WiFi";
    ไฟล์ secrets.h ถูกตั้งไว้ไม่ให้ขึ้น GitHub รหัส WiFi จึงไม่หลุดไปใน repo สาธารณะ
  5. เปิด cucumber_aiot.ino แก้ชื่ออุปกรณ์: 
    const char* DEVICE_ID     = "school123-group01";  // ห้ามซ้ำกับกลุ่มอื่น
  6. Tools → Board → ESP32S2 Dev Module, USB CDC On Boot: Enabled, PSRAM: Enabled
  7. ครั้งแรก ให้บอร์ดเข้าโหมดอัปโหลด: กดปุ่ม BOOT ค้าง → กด RESET → ปล่อย BOOT แล้วเลือกพอร์ตและกด Upload (หลังอัปโหลดเสร็จกด RESET อีกครั้ง)
  8. เปิด Serial Monitor (115200) จะเห็นค่าที่ส่ง เช่น
    -> {"id":"school123-group01","temp":29.4,"hum":63.1,"pres":1008.6,"ax":0.12,...}

กิจกรรม: ทดลองกับเซนเซอร์
  1. เป่าลมหายใจใส่บอร์ด ค่าความชื้นเปลี่ยนอย่างไร? ใช้เวลานานแค่ไหนจึงกลับมาเท่าเดิม
  2. เคาะโต๊ะเบา ๆ ค่า ax ay az เปลี่ยนอย่างไร? ทำไม az ถึงอยู่ประมาณ 9.8 ตอนวางนิ่ง
  3. ถือบอร์ดขึ้นบันได 1 ชั้น ความกดอากาศลดลงกี่ hPa?

บทที่ 3 · ส่งข้อมูลขึ้นอินเทอร์เน็ตด้วย MQTT

1 คาบบอร์ด + มือถือ

จุดประสงค์

  • อธิบายหลักการ Publish / Subscribe และ Topic ได้
  • เชื่อมบอร์ดกับ Dashboard บนมือถือได้

MQTT เหมือนกลุ่มแชท

Broker คือเซิร์ฟเวอร์กลาง (เหมือนแอปแชท) · Topic คือชื่อห้องแชท · Publish คือส่งข้อความเข้าห้อง · Subscribe คือเข้าร่วมห้องเพื่อรับข้อความ ผู้ส่งกับผู้รับไม่ต้องรู้จักกันโดยตรง

Topicใครส่ง → ใครรับตัวอย่างข้อความ
aiot-classroom/<ID>/sensorsบอร์ด → เว็บ{"temp":29.4,"hum":63.1,...}
aiot-classroom/<ID>/ledเว็บ → บอร์ด{"r":0,"g":255,"b":0,"label":"comfy"}
aiot-classroom/<ID>/statusบอร์ด → เว็บonline / offline

ขั้นตอน

  1. เปิด Dashboard บนมือถือ เลือก "บอร์ด Cucumber จริง"
  2. พิมพ์ DEVICE_ID ให้ตรงกับในเฟิร์มแวร์ แล้วกด "เชื่อมต่อ"
  3. เมื่อสถานะเป็น "รับข้อมูลจากบอร์ดอยู่" ค่าเซนเซอร์และกราฟจะอัปเดตทุก 2 วินาที

broker ที่ใช้เป็นแบบสาธารณะ ใครที่รู้ Topic ก็อ่านได้ ชวนนักเรียนคุยว่า "ถ้าเป็นข้อมูลสุขภาพหรือกล้องในบ้าน ควรทำอย่างไร?" (คำตอบ: ใช้ broker ส่วนตัว + รหัสผ่าน + เข้ารหัส TLS)

กิจกรรม: แลกห้องกัน

ให้กลุ่ม A พิมพ์ DEVICE_ID ของกลุ่ม B ใน Dashboard จะเห็นข้อมูลของอีกห้อง/อีกมุม และสามารถเปลี่ยนสีไฟบนบอร์ดของกลุ่ม B ได้ด้วย นี่คือเหตุผลที่ระบบจริงต้องมีการยืนยันตัวตน

บทที่ 4 · เก็บข้อมูลและเทรน AI บน Google Colab

2 คาบบอร์ด + มือถือ + คอมพิวเตอร์

จุดประสงค์

  • อธิบายคำว่า Feature, Label, Training set, Test set ได้
  • เก็บข้อมูลที่มีป้ายกำกับ เทรนโมเดล และอ่านผล confusion matrix ได้

Machine Learning ใน 1 นาที

แทนที่เราจะเขียนกฎเอง เราให้ ตัวอย่าง กับคอมพิวเตอร์ เช่น "29 °C, ชื้น 80% → อบชื้น" หลาย ๆ ตัวอย่าง แล้วให้มันหารูปแบบเอง ค่าที่ป้อนเข้า (temp, hum) เรียกว่า Feature คำตอบที่ถูก (อบชื้น) เรียกว่า Label

คาบที่ 1: เก็บข้อมูล

  1. ใน Dashboard ส่วน "③ เก็บข้อมูลสอน AI" เลือกป้ายตามความรู้สึกของคนส่วนใหญ่ในกลุ่ม แล้วกด "บันทึกต่อเนื่อง"
  2. เปลี่ยนสภาพแวดล้อมเพื่อให้ได้ข้อมูลหลากหลาย: ปิด/เปิดพัดลม, ไปใกล้หน้าต่างที่มีแดด, ห้องแอร์, ใกล้กาต้มน้ำ (ระวังความร้อน)
  3. พยายามให้มี อย่างน้อย 30 แถวต่อป้าย แล้วกด "ดาวน์โหลด CSV"

คาบที่ 2: เทรนบน Colab

  1. เปิด notebook บน Google Colab
  2. เซลล์แรก ตั้ง UPLOAD_MY_CSV = True แล้วอัปโหลดไฟล์ CSV ของกลุ่ม
  3. รันทีละเซลล์ ดูกราฟการกระจายของข้อมูล → เทรน → ดู confusion matrix และแผนที่การตัดสินใจ
  4. เซลล์สุดท้ายจะดาวน์โหลด comfort_model.zip (มี model.json, weights.bin, meta.json)
คำถามชวนคิด
  1. ทำไมต้องแยกข้อมูล test ไว้ไม่ให้โมเดลเห็นตอนเทรน?
  2. ถ้ากลุ่มหนึ่งขี้ร้อน อีกกลุ่มขี้หนาว โมเดลของสองกลุ่มจะต่างกันอย่างไร? AI แบบนี้ "ถูก" หรือ "ลำเอียง"?
  3. ถ้าข้อมูล "อบชื้น" มีน้อยมาก โมเดลจะทายคลาสนี้ได้ดีไหม? ทดลองดูได้ใน notebook

บทที่ 5 · AI บนมือถือ และปิดวงจรด้วยไฟ LED

1 คาบบอร์ด + มือถือ

จุดประสงค์

  • อธิบายข้อดีของการรัน AI บนอุปกรณ์ (Edge AI) ได้
  • นำโมเดลของกลุ่มไปใช้งานจริงและทำให้ระบบตอบสนองได้

สองทางในการนำโมเดลไปใช้

ทาง A: อัปโหลดขึ้น GitHub

แตกไฟล์ zip แล้วอัปโหลด 3 ไฟล์ทับของเดิมใน docs/model/ ของ repo (Add file → Upload files → Commit) รอ 1–2 นาที ทุกคนที่เปิดเว็บจะได้โมเดลใหม่

ทาง B: เทรนบนมือถือเลย

ใน Dashboard กด "④ เทรนบนมือถือ" ใช้ข้อมูลที่เก็บในเครื่องนั้น เทรนเสร็จในไม่กี่วินาที (โมเดลอยู่เฉพาะเครื่องนั้นจนกว่าจะรีเฟรชหน้า)

ปิดวงจร: วัด → ส่ง → คิด → ตอบสนอง

เมื่อ AI ทำนายผล หน้าเว็บจะ publish สีไปที่ …/led บอร์ดจะเปลี่ยนสีไฟทันที นี่คือส่วน Act ของระบบ ลองเป่าลมใส่บอร์ดหรือนำไปใกล้แหล่งความร้อน แล้วดูว่าไฟเปลี่ยนสีตามหรือไม่

ทำไมต้องรัน AI บนมือถือ (Edge AI)?

  • ความเป็นส่วนตัว ข้อมูลไม่ต้องส่งไปเซิร์ฟเวอร์ของใคร
  • ไม่ต้องมีเซิร์ฟเวอร์ เว็บเป็นไฟล์ static บน GitHub Pages ฟรี
  • เร็ว ทำนายได้ในเสี้ยววินาที แม้เน็ตช้า
โปรเจกต์ต่อยอด (เลือก 1 อย่าง)
  • ตรวจจับการเปิดประตู: ติดบอร์ดที่ประตู ใช้ค่า ax ay az จาก MPU-6050 สอน AI แยก "เปิด/ปิด/ไม่มีอะไร"
  • พัดลมอัตโนมัติ: ต่อรีเลย์ที่ขา GPIO ของบอร์ด ให้เปิดพัดลมเมื่อ AI บอกว่า "ร้อนไป"
  • แจ้งเตือนผ่าน Telegram: เพิ่ม bot ส่งข้อความเมื่อห้องร้อนติดต่อกันเกิน 10 นาที

สำหรับครู: การประเมินผล และแก้ปัญหา

เกณฑ์การประเมิน (Rubric)

หัวข้อดีมาก (3)พอใช้ (2)ปรับปรุง (1)
ระบบ IoTบอร์ดส่งข้อมูลขึ้น Dashboard และรับสีไฟกลับได้ส่งข้อมูลได้ แต่ยังไม่รับคำสั่งกลับอ่านค่าได้เฉพาะใน Serial Monitor
ข้อมูล≥30 แถว/ป้าย หลายสภาพแวดล้อมมีครบทุกป้ายแต่ไม่สมดุลขาดบางป้าย
โมเดล AIอธิบาย confusion matrix และเหตุที่ทายผิดได้เทรนสำเร็จ อ่านค่าความแม่นยำได้เทรนไม่สำเร็จ
การนำเสนออธิบายวงจร วัด/ส่ง/คิด/ตอบสนอง และข้อจำกัดได้อธิบายได้บางส่วนอธิบายไม่ได้

ปัญหาที่พบบ่อย

อัปโหลดไม่ได้ / หาพอร์ตไม่เจอ

เข้าโหมดอัปโหลด: กด BOOT ค้าง → กด RESET → ปล่อย BOOT ใช้สาย USB ที่ส่งข้อมูลได้ (ไม่ใช่สายชาร์จอย่างเดียว)

Serial Monitor ไม่ขึ้นอะไร

ตั้ง USB CDC On Boot เป็น Enabled แล้วอัปโหลดใหม่ และตั้งความเร็วเป็น 115200

ขึ้น HTS221:- (หาเซนเซอร์ไม่เจอ)

เฟิร์มแวร์จะลองสลับขา SDA/SCL (GPIO41/40) ให้อัตโนมัติ ถ้ายังไม่เจอ ตรวจว่าบอร์ดเป็นรุ่น RIS (มีเซนเซอร์) ไม่ใช่รุ่น R

ไฟบนบอร์ดเป็นสีฟ้ากะพริบไม่หยุด

ต่อ WiFi ไม่ได้: ESP32-S2 รองรับเฉพาะ 2.4 GHz ตรวจชื่อ/รหัส WiFi และ WiFi ของโรงเรียนที่ต้องล็อกอินผ่านหน้าเว็บจะใช้ไม่ได้ ให้ใช้ hotspot จากมือถือแทน

Dashboard เชื่อมต่อแล้วแต่ไม่มีข้อมูล

DEVICE_ID บนเว็บต้องตรงกับในเฟิร์มแวร์ทุกตัวอักษร (ตัวพิมพ์เล็ก/ใหญ่มีผล) และเครือข่ายบางแห่งบล็อกพอร์ต 8884 ลองใช้ 4G

การใช้ AI เป็นผู้ช่วยพัฒนาโปรเจกต์นี้

โปรเจกต์นี้สร้างร่วมกับผู้ช่วย AI (Claude) โดยผู้พัฒนาเป็นคนกำหนดเป้าหมายและตัดสินใจ ส่วน AI ช่วยค้นข้อมูล เขียนโค้ด และทดสอบ

ขั้นตอนสิ่งที่ขอให้ AI ทำสิ่งที่มนุษย์ต้องตรวจ
ออกแบบเสนอโจทย์ที่เหมาะกับนักเรียน ม.ปลาย และสถาปัตยกรรมระบบเลือกกลุ่มเป้าหมาย ที่รัน AI และรูปแบบ UI
ค้นสเปกบอร์ดหาเซนเซอร์และขาของ Cucumber RISAI พบว่าแหล่งข้อมูลระบุขา I2C ขัดกันเอง จึงให้เฟิร์มแวร์ลองทั้งสองแบบ ต้องยืนยันกับบอร์ดจริง
เขียนโค้ดเฟิร์มแวร์ Arduino, notebook Colab, หน้าเว็บ Dashboardอ่านโค้ด ทดสอบบนบอร์ดจริง
ทดสอบทดสอบวงจร MQTT → AI → LED ผ่าน broker จริงด้วยบอร์ดจำลองทดสอบซ้ำกับบอร์ดจริงในห้องเรียน
เอกสารร่างบทเรียน คำถาม และ rubricปรับภาษาและเวลาให้เหมาะกับห้องเรียนจริง

ข้อคิดสำหรับนักเรียน

  • AI เขียนโค้ดได้เร็ว แต่ อาจผิดหรือมั่นใจเกินจริง ต้องทดสอบเสมอ
  • ถาม AI ให้ อธิบาย โค้ดทีละส่วน จะเรียนรู้ได้มากกว่าการคัดลอก
  • บอกบริบทให้ชัด (บอร์ดรุ่นไหน ใช้ไลบรารีอะไร ใครเป็นผู้ใช้) คำตอบจะตรงขึ้นมาก
